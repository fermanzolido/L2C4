## 2026-06-20 - [Optimizing World Visibility and Packet Construction]
**Learning:** Replacing LinkedList with ArrayList in hot paths like visibility checks and packet construction significantly reduces memory allocations and improves cache locality. Pre-allocating ArrayList capacity using a size hint (e.g., surrounding objects count) further eliminates overhead from internal array resizing. In L2J Mobius, specific script-based target handlers still return LinkedList, so core filtering logic (e.g., Skill.java) must remain compatible with both ArrayList and LinkedList to avoid ClassCastException or missing optimizations.
**Action:** Always prefer ArrayList for collection results in hot paths and provide an initial capacity hint whenever possible. Update target handling logic to be implementation-agnostic or explicitly support both ArrayList and LinkedList.
