## 2026-07-01 - LinkedList Anti-pattern in Visibility and Skill Logic
**Learning:** Core visibility methods in `World.java` and `InstanceWorld.java` often return `LinkedList`, but `Skill.java` contains explicit `instanceof LinkedList` checks before performing in-place filtering (`removeIf`). Optimizing these methods to return `ArrayList` without updating the type checks in `Skill.java` (and potentially other script handlers) causes logic regressions where monster buffs are not correctly filtered for players.
**Action:** When refactoring visibility or collection methods from `LinkedList` to `ArrayList`, always grep for `instanceof LinkedList` to ensure downstream filtering logic is preserved. Prefer `ArrayList` with pre-allocation via `getSurroundingObjectsCount` for hot-path visibility loops to improve CPU cache locality.
